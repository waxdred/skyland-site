Coming from Hyprland

skyland's default profile follows 43PR's Hyprland dotfiles. Super mostly becomes alt or cmd (macOS keeps cmd for app shortcuts), and the config is TOML in ~/.config/aerospace/aerospace.toml. Here is where your habits went.

Window rules

windowrulev2 = float, class:^(org.gnome.Nautilus)$ and friends become a block per match:

[[on-window-detected]]
if.app-id = 'com.apple.finder'
run = ['layout floating', 'window-rule size 60% 70%', 'window-rule center',
       'window-rule opacity 95 85', 'window-rule rounding 14', 'window-rule noanim']

size and move take points or a percentage of the screen and need the window floating; noborder, nodim and noanim turn effects off for that window. Match on app-id, app-name-regex-substring, window-title-regex-substring or the workspace. The Rules tab of the settings window (alt-i) edits them too.

Animations

Pick a preset, or paste your Hyprland lines over it:

[animations]
enabled = true
preset = 'hyprland'   # hyprland | slide | gnome | vertical | cyberspace
bezier = ['myBezier, 0.05, 0.9, 0.1, 1.05']
animation = [
  'windows, 1, 5, myBezier, popin 80%',
  'workspaces, 1, 6, default, slidevert',
]

Speeds are in Hyprland's deciseconds (speed 5 = 500 ms). Windows open, close and move, workspaces slide, fades and dim follow these tracks.

What is different on macOS

  • skyland is not the compositor. It moves other apps' windows from the outside, so an app that is slow to resize (Electron) lags behind a little, where Hyprland would be frame-perfect.
  • The effects need the Dock payload, hence SIP partly off. Without it you keep tiling and the whole desktop, not the corners, opacity and animations. See Install.
  • Native fullscreen and minimize are macOS's own; skyland handles them (macos-native-fullscreen, macos-native-minimize), but prefer skyland's fullscreen.
  • One macOS Space per display. skyland's workspaces replace Spaces; extra Spaces confuse it.
