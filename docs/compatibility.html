What a macOS update can break

  • The window effects. They use private SkyLight functions, called from the payload injected into Dock. Apple can change them in any update; the payload's commands then fail and skyland runs without effects. Tiling and the desktop do not use them.
  • The injection. It needs the -arm64e_preview_abi boot-arg and Dock's arm64e ABI (skyland sa build prints abi: USR00).
  • Building from source. A new Command Line Tools SDK can break the Swift toolchain's linker (with the macOS 27 SDK, Swift 6.4.1 fails with libSystem.B.tbd: unknown architecture). Build against the previous SDK: SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk bin/skyland-build. Homebrew and the release zip are not affected.

Checking a version

skyland doctor                          # permissions, payload, dependencies
bin/skyland-sa build                    # the payload and its unit tests: "payload ok"
swiftc -O tools/e2e-visibility.swift -o .build/e2e-visibility
.build/e2e-visibility 11 12 40          # two spare workspaces; hands off for 2 minutes

e2e-visibility opens windows, then switches, moves, closes and opens them at random, and fails if a window of the shown workspace ends up off screen or see-through. To check the crash guard: make a window fade (skyland-sa send fade <id> 0 8000 0 0 1 1), kill -9 Skyland halfway: the window must be opaque again within a second.
